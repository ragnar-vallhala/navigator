# Navigator profiling report, 2026-11-11

Status: measurements only, no optimisation applied. Measured on origin/main d89ff67 (before the world-change floor fix, the GPU-grass mask fix and the dock host merged). The measuring harness is on branch `perf/profile-harness` (not merged); raw per-run data stayed in the author's scratch directory and is not in the repository.
Measured on an RTX 3050 (X11, GNOME compositor, 60 Hz, shared desktop with 34-39% GPU baseline), 3 runs per scenario. Software-GL (llvmpipe) numbers are for comparison only.

Base: origin/main d89ff67 (measured). Branch perf/profile-harness merged with later main afterwards (not re-measured).
Raw data: scratchpad/perfdeep/runs/*.jsonl (+ .smi GPU log, .pre nvidia-smi snapshot, .load loadavg, .stacks samples).

## Method
- In-app harness (NAVIGATOR_PROFILE=<scenario>, default OFF, inert): paint-level frame interval of the sim 3D window ("main"), the down-cam window ("down") and Drone3DWidget; per-section CPU scopes; GL_TIME_ELAPSED GPU time; 5 ms-timer event-loop lag; per-thread CPU from /proc; per-event-type time table; in-process SIGPROF CPU-time stack sampler (perf and gdb attach unavailable).
- Machine: 12 cores, RTX 3050 on X11 :0 (3000x1920 desktop, GNOME compositor), app window 1600x900 requested, vsync 60 Hz. Desktop was shared: baseline 34-39 % GPU util, ~510 MiB used (firefox, qemu, gnome-shell, nautilus), loadavg 3.5-8 from other work. 3 repetitions per scenario, bracket = min-max over runs.
- Software GL = llvmpipe on private xvfb-run (saturates all cores; NOT representative, only for comparison).
- Not measured: docked scenarios 5/9 (PR #35 needs Qt Advanced Docking System, not installed, no network), nsys (not tried), display/compositor effects other than via the swap-interval experiment.

## Ranked bottlenecks (gain vs effort)

### 1. Three serialized vsync waits on the GUI thread: sim view runs at 20 Hz, event loop 45 ms late (MEASURED cause by experiment)
- Evidence: main.interval_ms mean 50.0 (p50 49.99, spread <1 ms) in every GPU scenario; evloop.lag mean 45.0 ms (a 5 ms timer fires once per 50 ms); GUI main thread only 14-30 % CPU, so it is blocked, not busy. paint_to_swap: main window 9.7-13 ms, down-cam window 15.2-16.2 ms, plus the UpdateRequest flush of the top-level window ~17 ms (events table: UpdateRequest ~340 ms/s). 3 x 16.7 ms = 50 ms.
- Control experiment (NAVIGATOR_SWAP_INTERVAL=0, 3 runs each): sim main interval p99 20.7 ms [19.7-21.6], max 24 ms, evloop lag 0.01 ms; endless p99 32 ms, lag 1.1 ms; endless + GPU grass p99 32 ms, lag 3.5 ms. Frame rate then follows the 62.5 Hz pose stream. (__GL_SYNC_TO_VBLANK=0 had no effect under the compositor.)
- Cause hypothesis (confidence high on mechanism, medium on exact split): SimRendererWidget and the down-cam are two native QOpenGLWindows (swap interval 1) plus the widget window flush; each blocks the single GUI thread.
- Fix: swap interval 0 on the down-cam window (and drive redraw from one frame timer), or render the down-cam into an FBO inside the main window context / only when visible, so one vsync wait per frame. Expected gain: 20 Hz -> ~60 Hz, input/event lag 45 ms -> ~1-4 ms. Effort: small. Risk: low-medium (tearing if interval 0 on the visible window; keep 1 on exactly one window).
- This is the most likely cause of "laggy at times" (inferred link to the user's perception).

### 2. Contour minimap samples the terrain noise on the CPU in the GUI thread (MEASURED)
- ContourMinimapWidget::paintEvent ~13.8 ms per paint (llvmpipe/GPU run: minimap.paint_ms mean 13.8), ~8-10 Hz; event table: ~120-126 ms/s on endless. Stack sampler (endless, GUI thread): 35.5 % inclusive in TerrainField::height via the minimap sampler lambda (Noise::fbm/gradient/cornerGradient/ridged), i.e. about 1/3 of all GUI CPU.
- Fix: cache the height grid and only resample when the view/centre moves by a cell, or compute in the pool thread. Expected gain: ~12 % of one core, removes ~13 ms frame spikes. Effort small. Risk low.

### 3. Synchronous world change on the GUI thread: 200-380 ms freeze (MEASURED)
- worldchange, 3 runs: iteration max alpine 323-381 ms, hills 283-303, desert 217-250, meadow 195-201; sim.loadWorldMesh_ms alone 135-307 ms. Switching into endless 66-118 ms. Sampler: loadWorldMeshToRenderer -> generateProceduralWorld / meshArena / meshFieldChunk on the GUI thread (7.6 % of GUI CPU during the sequence).
- Fix: generate/mesh arenas on the thread pool (the endless path already does) and upload on completion; expected gain: freeze -> <20 ms per frame. Effort medium. Risk medium (stale-config races, there is an existing cancelWorldShip pattern). Note main has since merged #34 world-change-floor (not re-measured).

### 4. CPU flora path is unusable on a real GPU; GPU grass is OK but costs GPU time (MEASURED)
- CPU grass (NAVIGATOR_GRASS_CPU=1, grass build): GPU scene 34.5 ms per frame, interval 116 ms (8.6 Hz), RSS 1.56 GB. GPU grass: 9.7 ms [swap1] / 5.8 ms [swap0] vs 7.0 / 2.1 ms without grass, i.e. about +3.7 ms GPU per frame; main CPU 73 % at swap0, process 93 %.
- Fix: keep GPU grass the default whenever compute is available; make the CPU fallback much sparser or off. Gain: avoid 4x frame cost on GPUs without compute. Effort small.

### 5. HUD overlay drawn by QPainter on the CPU and re-uploaded (MEASURED cost, mechanism INFERRED)
- main.hud_cpu_ms 3.5-6 ms per frame at swap1 (1.2 ms at swap0 with fewer samples/clean CPU clock), GPU part main.gpu_hud_ms 1.4-2.9 ms (larger than the 3D scene in sim: scene 0.6 ms). Sampler (sim): paintHud 31 %, SimHudWidget::paintEvent 21 %, drawPolyline 10 %, libc memcpy ~11 % self of GUI CPU. Full-window ARGB image is built and drawImage'd every frame.
- Fix: draw HUD into a cached texture, redraw only changed parts, or shrink to dirty rects. Expected gain: 2-4 ms/frame, ~20-30 % of GUI CPU, 2 ms GPU. Effort medium. Risk low.

### Lesser items
- Down-cam renders a full second scene every frame (down.paint_cpu 0.06-0.4 ms, GPU 0.04-3.0 ms; 2 ms GPU on endless) even when likely not visible: gate on visibility (MEASURED cost, small).
- Startup hitches (first paint, shader link): 100-550 ms once (MEASURED, sw and gpu).
- Home idle is cheap: 1.5 % CPU. Many QLabel StyleChange events at idle (inferred minor churn).
- Telemetry: updateHud 0.003 ms, onUartBytes 0.006 ms, logGroundTruth 0.004 ms, onUiTimer 0.15 ms: NOT a bottleneck. SimWorker 2-8 % CPU (7 % endless), 1 kHz engine step, pose every 16 ticks (62.5 Hz) exact. Pool threads ~1 % each. No leak over 60 s.

## Noise
- Repetition spread is small for plateau metrics (interval 50.0, lag 45.0 identical across runs), larger for worst cases (max/p99 vary 2x, e.g. alpine p99 57-135 ms) because the desktop is shared (compositor, firefox, qemu, loadavg 3.5-8). GPU numbers depend on GPU clock state: the same endless scene is 7.0 ms GPU at swap1 (GPU idles at 200-900 MHz while waiting) and 2.1 ms at swap0; compare GPU ms only within the same swap mode. Single desktop, single resolution (1600x900 window), no input events driven.
